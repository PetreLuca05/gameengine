# Deadground

First-person co-op zombie survival foundation in **C11** on **SDL3 + Vulkan 1.3**, with
Jolt physics (via `joltc`), ENet LAN networking and an optional Steam transport.
Milestone 1 is a **DevRoom**: a 60×60 m test level that exercises every core system.

Characters (players, test zombies, dummies) are skinned FBX models on one shared skeleton:
* a data-driven animation controller;
* procedural IK and weapon holding;
* per-body-part damage;
* Jolt ragdolls;
* character LODs.

Zombie AI is still a test wander / attack behaviour. See [ARCHITECTURE.md](ARCHITECTURE.md),
[docs/ANIMATION.md](docs/ANIMATION.md), [docs/DAMAGE.md](docs/DAMAGE.md),
[docs/ANIMATION_NET.md](docs/ANIMATION_NET.md) and [docs/RECOIL.md](docs/RECOIL.md).

## Building

### Windows

From an *x64 Native Tools Command Prompt* (or any shell where `cl`, `cmake`, `ninja` and a
GLSL compiler are on `PATH`):

```bat
build.bat                 :: RelWithDebInfo -> build\bin\deadground.exe
build.bat Debug           :: Debug          -> build-debug\bin\deadground.exe
```

Or by hand:

```bat
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build
```

clang-cl:

```bat
cmake -S . -B build-clang -G Ninja -DCMAKE_C_COMPILER=clang-cl -DCMAKE_CXX_COMPILER=clang-cl
cmake --build build-clang
```

`build.bat` also looks for a local `.toolchain\env.bat`. That's how this repo was built on a machine
with only VS 2019 Build Tools, plus portable CMake, Ninja and glslang. It's optional and git-ignored.

### Linux

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build
./build/bin/deadground
```

### Steam (optional)

Point `STEAM_SDK_DIR` at the Steamworks SDK `sdk` folder, the one containing
`public/steam/steam_api.h` and `redistributable_bin/`:

```sh
cmake -S . -B build -DSTEAM_SDK_DIR=/path/to/steamworks/sdk     # or set the env var STEAM_SDK_DIR
```

Configure prints `Deadground: Steam transport ENABLED`. The steam_api DLL/SO is copied next to the exe
and `steam_appid.txt` is written with AppID **480** (Spacewar) for development. Put your own AppID there
for release. Without `STEAM_SDK_DIR`, the build is LAN-only and the Steam UI entries are disabled.

### Shaders

GLSL lives in `shaders/` and is compiled to SPIR-V at build time into `build/bin/shaders/`.
In dev builds the game watches `shaders/*` and **hot-reloads** on save. It recompiles with the
compiler found at configure time and rebuilds the pipelines. `r_reloadshaders` forces a reload.

### Placeholder assets

`assets/` is generated by `python tools/gen_assets.py`. It's pure Python with no packages and produces
WAV sounds, a PNG crate texture, a KTX2 texture and a glTF barrel. The generated files are committed.

### Character and animation assets

`assets/human/*.fbx` (the canonical rig `Dummy.fbx` and its clips) load directly through ufbx.

* **Bake cache.** On first load they're baked into `assets/cache/`, keyed by file hash. Edited files
  re-bake automatically. `--rebuild-cache` forces a full re-bake.
* **Tools.** `bake_anim` bakes offline and prints a report. `validate_rig <fbx|dir>` checks rigs
  against the canonical skeleton.
* **Data.** Characters are `assets/characters/*.json`. Controller, anim sets, clip metadata, ragdoll
  and hitboxes live in `assets/human/*.json`. See [docs/ANIMATION.md](docs/ANIMATION.md).

## Running

```sh
deadground                      # boots into the DevRoom as a listen host (LAN open on UDP 27015)
deadground +map streaming       # chunk-streamed noise terrain demo (also: +map flat)
deadground +set g_map streaming # make the streaming demo the default boot map (saved to config)
deadground --validation         # Vulkan validation layers (needs the layer installed)
```

Settings autosave about a second after a change (and on exit, only if something changed), to
`config.cfg` in the user pref dir. The previous file is kept as `config.cfg.bak`. Builds never touch
it, and `--test` runs neither read nor write it.

Config, log and screenshots go to the user pref dir. On Windows that's
`%APPDATA%\Deadground\Deadground\`, which holds `config.cfg` and `deadground.log`.

### Two LAN instances on one machine

1. Start the host: `deadground`. Every game is a listen server, and LAN hosting starts automatically (`net_autohost 1`).
2. Start a second instance and connect:
   ```sh
   deadground +set cl_name Player2 +connect 127.0.0.1
   ```
   You can also use **Esc → Multiplayer → Refresh**: the LAN browser finds the host via UDP broadcast on
   port 27016. Then click **Join**, or type an address under **Direct connect**.
3. Test bad networks on either instance: `net_fakelag 120`, `net_fakeloss 5`, `net_fakejitter 20`.
   Turn on the overlay with **F3** or `net_showstats 1`.

Across machines, run `connect <host-ip>:27015` (allow UDP 27015/27016 through the firewall).
With Steam: on the host, **Esc → Multiplayer → Host Steam lobby**. Friends can then join from the
Steam friends list or via **Invite Friends** (the overlay invite dialog), or with `connect_lobby <id>`.

## Controls (defaults, all rebindable)

| Action | Key |
|---|---|
| Move | W A S D |
| Jump / mantle / pull up | Space (hold while airborne to grab ledges) |
| Crouch / drop from ledge | Left Ctrl |
| Sprint (sprint into low walls to vault) | Left Shift |
| Slow walk | Left Alt |
| Use / interact (hold for crates) | E |
| Attack / fire / use consumable (hold) | Mouse 1 |
| Aim down sights | Mouse 2 |
| Hold breath (while aiming) | Left Shift |
| Fire mode (auto / burst / single) | B |
| Reload | R |
| Drop held item | G |
| Hotbar | 1–9, mouse wheel |
| Inventory | Tab (click two slots to move, right-click to drop) |
| Net stats | F3 |
| Console | ~ |
| Pause menu | Esc |

The gamepad works through SDL3: sticks, south = jump, east = crouch, west = use, triggers = aim/fire.

## Console

`cvarlist [filter]`, `cmdlist`, `bindlist`, `bind <key> <action> [slot]`, `exec <file>`, `writeconfig`.

Useful commands: `map <devroom|streaming|flat>`, `host [lan|steam]`, `connect <ip[:port]>`,
`disconnect`, `lan_refresh`/`lan_list`, `give <item> [count]`, `noclip`, `kill`, `setpos x y z [yaw] [pitch]`,
`getpos`, `lookat x y z`, `inv`, `status`, `screenshot [path]`, `r_reloadshaders`, `hands_reload`,
`menu <pause|settings|controls|crosshair|audio|multiplayer|close>`, `quit`.

Characters and animation are listed in full in [docs/ANIMATION.md](docs/ANIMATION.md):
* zombies: `zombie_spawn [n] [id] [radius]`, `zombie_attack`, `zombie_clear`;
* characters: `char_spawn <id> x y z [yaw] [item]`, `char_kill`, `char_list`, `ragdoll [push N]`;
* debug panel: `anim_target`, `anim_solo` / `anim_mute` / `anim_force`;
* test stand: `anim_stand` + `anim_stand_*`;
* LOD: `anim_lod_lineup`;
* hot reload: `anim_reload`, `anim_rebake`, `character_reload`, `hitbox_reload`, `anim_template`;
* aiming aid: `aimat <part>`.

Weapons: `wpn_magdump [weapon] [10|25|50] [ads]` stands you on the DevRoom recoil lane and empties a
magazine at the 10 / 25 / 50 m grid wall. It logs the fire mode, measured RPM and view climb, and
checks every bullet against its cone (PASS/FAIL). `weapon_reload` re-reads `data/weapons/*.json` for
live tuning, and `crosshair_reload` re-reads `assets/ui/crosshair.json`. See [docs/RECOIL.md](docs/RECOIL.md).

### Settings

Graphics, controls and audio settings are cvars and persist to `config.cfg`, along with key binds.
In the menu, graphics changes take effect on **Apply**. Resolution and window-mode changes revert
after a 15 s countdown unless you confirm them.

## Automated test scripts

`--test` disables config load/save and audio and caps the game at 60 FPS. `--script <file>`
queues console commands. `wait N` waits N frames (one sim tick per frame at 60 FPS).
`screenshot <path>` captures the next presented frame. Example scripts are in `tools/tests/`:

```sh
deadground --test --script tools/tests/traverse.cfg     # mantle / ledge hang / pull-up / vault
deadground --test --script tools/tests/interact.cfg     # pickups, pistol, dummies, reload
deadground --test --script tools/tests/doors.cfg        # door knob IK, locked door, lever + gate, crate
deadground --test --script tools/tests/weapons.cfg      # bat, rifle, shotgun, crossbow, light switch
deadground --test --script tools/tests/recoil.cfg       # mag dumps of every preset at the recoil wall
deadground --test --script tools/tests/recoil_modes.cfg # auto / burst / single + measured RPM
ctest --test-dir build                                  # unit tests: recoil, anim, ragdoll (Jolt)
deadground --test --script tools/tests/anim_stand.cfg   # animation test stand: clip scrub, items, hits, ragdoll
deadground --test --script tools/tests/anim_kill.cfg    # hitbox overlay, death -> ragdoll
deadground --test --script tools/tests/anim_lod.cfg     # LOD line-up at 5/15/30/60/120 m (flat map)
deadground --test --script tools/tests/ui.cfg           # menus, inventory, console
deadground --test +map streaming --script tools/tests/stream.cfg
# two-instance LAN test:
deadground --test --script tools/tests/net_host2.cfg &
deadground --test +connect 127.0.0.1 --script tools/tests/net_lag_client.cfg
# animation / lag-compensated body parts / events (150 ms + 5 % loss), see docs/ANIMATION_NET.md:
deadground --test --script tools/tests/anim_net_host.cfg &
deadground --test +connect 127.0.0.1 --script tools/tests/anim_net_client.cfg
```

The scripts write screenshots to `C:/C/Game/build/`. Edit the paths for your checkout.

## Status and known limitations

* **Tested on Windows**: MSVC 19.29 (VS 2019 Build Tools) and an RTX 3060 Ti, with Vulkan validation
  enabled and no validation errors. Single-player, two-instance LAN with fake lag/loss, terrain
  streaming, all DevRoom interactions, and the menus were all exercised.
* **Steam transport is untested**: no Steamworks SDK was available while building it. The shim targets
  SDK 1.5x/1.6x (`ISteamNetworkingSockets`, lobbies, rich presence). Expect small API fixes when you
  first build with `STEAM_SDK_DIR`.
* **Linux**: compiles and links with GCC 13.3 (checked under WSL with a headless SDL build); running it
  needs a desktop session and a Vulkan driver and is unverified.
* **clang-cl**: no clang-cl was installed on the build machine, so that path is untested.
* Snapshot and event payloads embed some structs (`PlayerSim`, `GameEvent`, `UserCmd`) byte-for-byte.
  Host and clients must run the same build; the protocol version check enforces this.
* **Animation clips.** Only 13 clips ship: idle, walk, run, strafes, turns, jump, hang. Slots for
  crouch, prone, mantle / vault, attacks, death, reload / fire / equip and hit clips are unbound.
  Those states fall back (idle on the base layer, empty upper layers). Visually that's covered by
  the procedural systems (hold, reactions) and the ragdoll on death. Adding the clips is data only:
  bind them in `assets/human/anim_sets/*.json` (`anim_template` lists every slot).
* Zombie AI is a test behaviour (wander, attack on command). Ragdolls are cosmetic and per machine.
* TAA is a stub that falls back to FXAA. Point-light shadows aren't implemented; one shadowed sun is.
* KTX2: uncompressed and BCn levels only, without supercompression (no Basis transcoding).
* The voice volume slider is reserved: there's no voice chat.
